🌟 What is MCP (Model Context Protocol)?

🤖 Imagine if AI assistants could...

  • 🔌 Connect to your databases
  • 📁 Access your file systems
  • 🌐 Call external APIs
  • 🧮 Perform custom calculations
  • 📊 Generate real-time reports

That's exactly what MCP enables!

🎯 Why MCP Matters

MCP is a standardized protocol that allows AI assistants to discover and use external tools dynamically. Instead of being limited to their training data, AI can now:

🔍 Discover Available Tools

AI assistants can ask: "What tools are available?" and get a list of everything they can use.

📋 Understand Tool Capabilities

Each tool comes with a schema describing what it does and what parameters it needs.

⚡ Execute Tools Dynamically

AI can call tools with the right parameters and get results in real-time.

💡 Real-World Example

Imagine asking an AI: "What's the weather in Tokyo and how much would a flight cost from New York?"

With MCP, the AI could:

  1. Discover a weather tool and flight pricing tool
  2. Call the weather API for Tokyo
  3. Call the flight API for NYC to Tokyo prices
  4. Combine the results into a comprehensive answer

💻 Implementation

🧩 Understanding MCP Components

Every MCP server has these key components:

🖥️ Server Instance

The main server that handles all communication

🔧 Tool Definitions

Describes what tools are available and how to use them

⚡ Tool Handlers

The actual code that executes when a tool is called

🔌 Transport Layer

How the server communicates (we'll use stdio)

📝 Step-by-Step Code Implementation

1 Import Required Modules

Create src/index.ts and start with imports:

import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js';
2 Create Server Instance

Initialize the MCP server with basic info:

const server = new Server(
  {
    name: 'hello-world-mcp-server',
    version: '1.0.0',
    capabilities: {
      tools: {},
    },
  }
);
3 Define Available Tools

Tell AI assistants what tools are available:

// List available tools
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: 'say_hello',
        description: 'Say hello to someone',
        inputSchema: {
          type: 'object',
          properties: {
            name: {
              type: 'string',
              description: 'Name of the person to greet',
            },
          },
          required: ['name'],
        },
      },
      {
        name: 'get_time',
        description: 'Get current time',
        inputSchema: {
          type: 'object',
          properties: {},
        },
      },
      {
        name: 'calculate',
        description: 'Perform basic math calculations',
        inputSchema: {
          type: 'object',
          properties: {
            operation: {
              type: 'string',
              description: 'Math operation (add, subtract, multiply, divide)',
              enum: ['add', 'subtract', 'multiply', 'divide'],
            },
            a: {
              type: 'number',
              description: 'First number',
            },
            b: {
              type: 'number',
              description: 'Second number',
            },
          },
          required: ['operation', 'a', 'b'],
        },
      },
    ],
  };
});

🔍 Understanding Tool Schemas

Each tool definition includes:

  • name: Unique identifier for the tool
  • description: What the tool does (helps AI understand when to use it)
  • inputSchema: JSON Schema defining required parameters
4 Implement Tool Handlers

Add the actual functionality for each tool:

// Handle tool calls
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  switch (request.params.name) {
    case 'say_hello': {
      const name = request.params.arguments?.name as string;
      return {
        content: [
          {
            type: 'text',
            text: `Hello, ${name}! Welcome to the MCP world! 🌟`,
          },
        ],
      };
    }

    case 'get_time': {
      const currentTime = new Date().toLocaleString();
      return {
        content: [
          {
            type: 'text',
            text: `Current time is: ${currentTime}`,
          },
        ],
      };
    }

    case 'calculate': {
      const { operation, a, b } = request.params.arguments as {
        operation: string;
        a: number;
        b: number;
      };

      let result: number;
      switch (operation) {
        case 'add':
          result = a + b;
          break;
        case 'subtract':
          result = a - b;
          break;
        case 'multiply':
          result = a * b;
          break;
        case 'divide':
          if (b === 0) {
            throw new Error('Cannot divide by zero');
          }
          result = a / b;
          break;
        default:
          throw new Error(`Unknown operation: ${operation}`);
      }

      return {
        content: [
          {
            type: 'text',
            text: `${a} ${operation} ${b} = ${result}`,
          },
        ],
      };
    }

    default:
      throw new Error(`Unknown tool: ${request.params.name}`);
  }
});
5 Start the Server

Add the main function to start the server:

async function main() {
  const transport = new StdioServerTransport();
  await server.connect(transport);
  console.error('Hello World MCP server running on stdio');
}

main().catch((error) => {
  console.error('Server error:', error);
  process.exit(1);
});

💡 What's Happening?

When you run npm start, your server:

  1. Starts listening on stdio (standard input/output)
  2. Waits for JSON-RPC requests
  3. Responds with available tools or executes them

🧪 Testing Your Server

🎯 Why Testing Matters

Testing ensures your MCP server works correctly and helps you catch bugs early. We'll create three types of tests:

🤖 Automated Tests

Run all tests automatically to verify functionality

🎮 Interactive Tests

Manually test each tool with a user-friendly interface

📊 Comprehensive Tests

Detailed testing with performance metrics and edge cases

🔄 Running Tests

We've included several test scripts with your project:

1 Basic Automated Tests
npm test

Runs through all tools and verifies they work correctly

2 Comprehensive Test Suite
npm run test:comprehensive

Includes performance metrics and error handling tests

3 Interactive Testing
npm run test:interactive

Menu-driven testing where you can try each tool manually

🔍 Manual Testing

You can also test manually by sending JSON-RPC requests:

📋 List Available Tools

{"jsonrpc":"2.0","id":1,"method":"tools/list"}

👋 Test Say Hello

{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"say_hello","arguments":{"name":"World"}}}

⏰ Test Get Time

{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_time","arguments":{}}}

🧮 Test Calculator

{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"calculate","arguments":{"operation":"add","a":15,"b":25}}}

🎉 Expected Results

If everything works correctly, you should see:

  • ✅ All tests pass
  • ✅ Response times under 10ms
  • ✅ Proper error handling for invalid inputs
  • ✅ Correct JSON-RPC formatted responses

🛠️ Production Deployment Tips

🔒 Security Best Practices

  • Never hardcode API keys or passwords
  • Validate all input parameters
  • Implement rate limiting for expensive operations
  • Use HTTPS for any network communications
  • Add authentication for sensitive tools

⚡ Performance Optimization

  • Cache frequently accessed data
  • Use connection pooling for databases
  • Implement timeout handling for external APIs
  • Add monitoring and logging
  • Consider using a process manager like PM2
